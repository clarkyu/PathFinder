# 航向 PathFinder · 交互与 UI 设计逻辑（v2）

## 0. 一个核心判断

用户（刚高考完的学生、以及他们的家长）打开这个应用，不是来"使用功能"的，
而是来**渡过一段不确定的时期**的。

v1 的形态是"工具箱"：五个标签把测评、探索、决策平铺出来，用户需要自己想
"我现在该用哪个工具"。但处在迷茫期的人最缺的恰恰是这个判断力。

所以 v2 的形态改为"**领航员**"：应用知道你在航程的哪个位置，每次只把
**下一步**递到你手上。就像导航软件——没人浏览地图，人们听"前方路口左转"。

## 1. 三条设计原则

### ① 跟着旅程走，不是跟着功能走
报告的方法论本质是一条时间线：**出分前认识自己 → 出分后检验现实、做出
决策 → 录取后长期心态**。信息架构必须直接长在这条时间线上，而不是按
功能类型分组。功能（测评/心流/访谈/平衡单）降级为旅程中被唤起的"动作"。

### ② 一次只问一件事
v1 的测评（一屏一题、三个大按钮）是体验最好的部分——因为它最像对话。
v2 把这个模式推广到所有输入：记心流、加访谈、添方向，全部改为
**底部浮层 + 对话式提问**（"什么事让你忘记时间？"），替代成片的表单。
打字最少化：能点选就不打字（信号用 chips、程度用滑杆、归档用分段控件）。

### ③ 输入即沉淀，处处见回报
每一条记录都要"长"到一个看得见的地方——**罗盘**（我是谁）和**航海图**
（去哪里）。用户记的不是数据，是逐渐成形的自我画像；这种可见的积累本身
就是继续探索的动机。理论知识不再是"知识库"陈列，而是**在恰当时机出现**
（测评结果旁讲 RIASEC、家长页讲自我决定理论），完整库保留在"更多"里备查。

## 2. 身份与阶段：开场三问

首次启动用三屏对话完成定向（之后随时可改）：

1. **你是谁？** 考生 / 家长 —— 决定文案口吻与任务内容
   （考生看"做什么"，家长看"怎么陪、什么不该做"）
2. **到哪一步了？** 还没出分 / 已出分 / 已填报或录取 —— 决定旅程位置
3. 一句定心丸（来自报告：迷茫是 18 岁的发展任务本身），进入航程

## 3. 信息架构：五标签 → 三标签

```
此刻（Now）       罗盘（Compass）        航海图（Chart）
─────────        ─────────────         ──────────────
现在该做什么       我是谁                 我去哪里
· 阶段时间线      · RIASEC 雷达 + 三字码  · 方向池（候选方案）
· 下一步推荐卡    · 心流线索墙            · 决策平衡单（六维打分）
· 本阶段清单      · 成就动机模式          · 综合排序
· 调整信号        · 奥德赛三个五年        · 冲·稳·保看板
                 · 访谈收获语录
```

- "更多"不再占标签位：右上角入口收纳家长/考生指南、知识库、数据管理、关于。
- 旧链接全部 301 式重定向（#/assess → #/compass/quiz 等），数据结构不变。

## 4. 关键交互模式

| 场景 | v1 | v2 |
|---|---|---|
| 不知道做什么 | 看清单自己挑 | "下一步"推荐引擎：按阶段+身份+数据状态，给 1 张主卡 + 2 张次卡 |
| 记心流/访谈/方向 | 页面内长表单 | 底部浮层，对话式标题，3 个字段以内，完成即沉淀到罗盘/航海图 |
| 阶段流转 | 无概念 | 时间线节点可点切换，全应用内容随之改变 |
| 家长使用 | 内容藏在"更多" | 身份=家长时，"下一步"换成陪伴任务（只问不评判、把决定权交还…） |
| 理论学习 | 知识库自学 | 上下文中即时出现 + 库保留备查 |

推荐引擎规则（节选，按命中顺序取前三）：
- 出分前：未测评→校准罗盘；心流<3→记心流；奥德赛空→写三种五年；
  方向池<5→捞方向；无成就事件→写一件；全部完成→"等待也是航程"
- 已出分：方向池<3→补方向；访谈<2→约访谈；有≥2方案→去打分；
  有未归档→冲稳保；收尾→阳光志愿核对+老师把关
- 已录取：长期心态卡（两句话）+ 继续记录心流

## 5. 视觉语言

- **隐喻**：航海。深海蓝 `#1450A3` → 浅海青 `#19A7CE` 是"海"，
  暖纸白 `#F6F7F3` 是"图纸"，**珊瑚橙 `#FF7355` 只给一个东西用——
  "下一步"的行动按钮**（整个界面永远只有一个最亮的点）。
- **层级**：大标题只出现在"下一步"主卡上（22px+）；其余收敛，
  留白放大，卡片圆角 18px、阴影更轻。
- **动效**：CSS 级的轻动效——视图淡入上浮、浮层滑升、进度条过渡、
  时间线节点点亮。不引入任何库。
- **RIASEC 六色**保留（它是有信息含义的色彩，不是装饰）。

## 6. 迭代记录

### v2.1 · 导航明确性 > 隐喻纯度（依据用户反馈：页面导航不清晰）

v2.0 把隐喻当成了路标，这是个错误——隐喻应该做氛围，不该做导航：

- **标签 3 个 → 4 个，文案从隐喻改为功能**：此刻 / 探索 / 决策 / 更多。
  "罗盘""航海图"退为页面副标题（"探索 · 我是谁"）。用户扫一眼标签就该知道
  里面是什么，而不是先学会一套比喻。
- **"更多"从右上角齿轮恢复为底部标签**：家长专区、知识库、数据管理的
  可发现性 > 界面极简。无标注的图标入口对非重度用户等于不存在。
- **探索页顶部新增 2×2 功能导航网格**（测评 / 心流成就 / 奥德赛 / 访谈，
  带完成状态）：先给全景、再给内容，消除"这卡片是内容还是入口"的歧义。
- **时间线节点点击加二次确认**：它是"状态切换"而非"页面跳转"，
  两种语义长得一样必须有一个让步——确认框 + 节点下方加说明文字。

### v2.2 · 全面体检：健壮性、深色模式与可访问性

通过「独立代码审计 + 逐文件复查」做了一轮完整加固：

- **数据层消毒**（最重要）：载入与导入备份都经过 sanitize()——枚举白名单、
  数值钳位、非法 id 重新生成。封堵了"导入恶意备份注入脚本"（存储型 XSS）
  和"损坏数据导致首页白屏无法自救"两类高危问题；render() 另有兜底页。
- **离线可靠性**：SW 只接受「同源 + 200 + 非重定向 + HTML」的导航响应写入
  应用壳缓存（防机场/酒店强制门户污染）；安装预缓存绕过 HTTP 缓存；
  弱网导航 4 秒超时回退缓存壳。
- **深色模式**：全部中性色收敛为设计令牌，跟随系统 prefers-color-scheme；
  雷达图改为 CSS 类着色以随主题切换。
- **交互细节**：原地刷新不再重播入场动画、滑块键盘操作焦点不丢失、
  浮层支持 Esc / 焦点圈定 / 焦点归还 / 背景滚动锁定 / 路由切换自动收起；
  重新测评与导入覆盖前先确认；存储写入失败有提示；多标签页状态同步。
- **可访问性**：折叠面板 aria-expanded、浮层与开场屏 role=dialog、
  复选框可聚焦、:focus-visible 焦点环、移除整页 aria-live 噪音、
  顶栏标题用真实 h1。
- **已知取舍**：珊瑚橙 CTA 白字对比度约 2.7:1（低于 AA 的 4.5:1）——
  保留品牌识别度，以大号粗体与高亮底色补偿；后续可评估加深主色。

### v2.3 · 对比度达标 + 三个新工具

- **WCAG AA 对比度**：「下一步」CTA 改为深色文字配珊瑚底（≈5.5:1，原白字仅
  2.7:1）；冲/稳/保与访谈状态等实底 chip 统一换深色变体（红 #DC2626 /
  琥珀 #B45309 / 绿 #047857 / 灰 #64748B，白字均 ≥4.5:1）；珊瑚色系文字
  走 --cta-ink 令牌双主题适配。RIASEC 六型为身份色，按取舍保留原色。
- **新版本提示**：SW 控制器变更时弹出「应用已更新 → 立即刷新」提示条，
  用户不再被动等待两次访问。
- **位次定位**（决策第三个标签）：填全省位次 + 给目标补「往年最低位次」，
  按公开的经验法则给出冲稳保参考并可一键采纳——显著降低「位次怎么用」
  的门槛；以醒目免责声明强调非官方标准。
- **选科参考**（更多）：6 科选 3 的定性速查，结论仅锚定报告中的两个上海
  口径数据点（物化 99.9% / 政史地 52.9%），其余为定性描述——拒绝编造
  精确覆盖率数据。
- **测评分享图**：Canvas 端侧生成 1080×1500 PNG（三字码 + 雷达 + 六型
  条形 + 免责脚注），优先 Web Share，回退下载；不经任何服务器。

### v2.4 · 收尾三件套

- **打印版志愿表**（决策 → 冲稳保）：按冲/稳/保/未定分组的 A4 友好表格
  （院校/专业/城市/往年位次/综合分/备注 + 权重与位次摘要 + 免责脚注），
  新窗口打开可直接打印或存 PDF——给「请老师把关」这一步一个像样的载体。
- **奥德赛三版对比**：三个五年并排（标题 / 四仪表盘微型条 / 待解问题数），
  自动点出「此刻最心动的版本」，把发散的想象拉回一张可讨论的桌面。
- **备份互传**：数据管理新增「分享备份给另一台设备」（Web Share 文件，
  回退下载），家长⇄考生两台手机经微信/AirDrop 即可互传全部数据。
  取舍：不做扫码互传——完整备份体积超出二维码容量，诚实地走文件通道。

### v2.5 · 循环工程：系统自己会迭代

- **应用内反馈通道**（更多 → 意见反馈）：结构化生成反馈文本，预填 GitHub
  Issue 或一键复制转交；只含用户可见内容，零遥测承诺不破。
- **测试收编进仓库**：tests/smoke.mjs + package.json（jsdom 仅 devDep），
  CI 在每个 PR 上跑冒烟 + 语法 + 版本一致性检查。
- **自迭代管道**（.github/workflows/claude-loop.yml）：feedback Issue →
  Claude 自动分诊 → 维护者加 loop:approved → Claude 在 loop/issue-N 分支
  实现并补测试 → 开 PR → 人工合并 → 部署后回访。两道人工闸门 + 六条红线
  写入 docs/loop.md，作为对自动化系统的"宪法约束"。
- 本版本自身即按新流程交付：走分支 + PR，不直推 main。

## 7. 明确的取舍

- **不做**账号/云同步：数据本地是隐私承诺，也是 PWA 的长处。
- **不做**首页信息密度：v1 首页的 KPI 网格删除，计数沉到罗盘各区块里。
- **暂不做**深色模式与多语言：留待后续。
- 奥德赛保持"编辑器"形态不改对话式——长内容创作需要全览，
  对话式反而碍事（原则②的边界）。
